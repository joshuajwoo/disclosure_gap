# Case-study protocol and safeguards

The Disclosure Gap uses a personally meaningful disclosure question as a demanding software case study. Its primary output is a privacy-conscious, reproducible longitudinal data system—not a claim of psychological novelty or a tool that diagnoses, predicts, or treats social anxiety.

The default and public path is synthetic. Seeded cohorts exercise consent states, repeated check-ins, missingness, attrition, sparse denominators, contract changes, exports, and feature calculations. Their results are acceptance tests for the pipeline and must never be described as findings about people.

A real-data pilot is optional. It cannot begin until institutional review, final consent, security, and readiness requirements are cleared. If pursued, it will use the frozen optional analysis protocol and be described as limited and exploratory unless its design and sample support stronger claims. The engineering project remains successful if no pilot occurs or if its result is null or inconclusive.

## Document map

- `survey.md` fixes the structured case-study questions and missing-value choices.
- `instrument-decision.md` records the selected outcome instrument, permission, version, and scoring.
- `predictor-outcome-overlap.md` audits construct overlap and defines sensitivity exclusions.
- `preregistration.md` is the optional exploratory analysis protocol retained under its original filename for traceability.
- `limitations.md` separates software evidence, synthetic output, and limits of possible empirical interpretation.
- `consent.md` and `review-requirements.md` define gates for any work involving real participants.
- `data-dictionary.md` and `raw-to-feature-lineage.md` define field meaning and auditable transformations.

## Existing context

The motivating domain already includes research on social anxiety in everyday contexts, self-disclosure and help-seeking, safety behavior and emotional disclosure, and self-disclosure interventions for young people. `PLAN.md` links representative sources. Those literatures motivate careful measurement; they are not presented as gaps that this portfolio software alone will resolve.

Four weekly check-ins are deliberately sparse. They are sufficient to exercise temporal rules and missing-data behavior, but often insufficient for stable person- or relationship-level estimates. The product and reports must expose that insufficiency rather than coerce it into a score.
