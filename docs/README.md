# Documentation

Owns the case-study protocol, consent, data dictionary, threat model, operations, system/case-study card, and participant-facing language. Documentation must distinguish synthetic pipeline evidence from any optional empirical evidence. Approved real-participant documents must be immutable by version.

- `validation/`: synthetic usability review, change log, and reproducibility evidence
- `operations/`: deployment and operational runbook
- `release/`: public-artifact checklist and publishable engineering case study
- `system-card.md`: intended use, boundaries, validation, ethics, and failure modes
